rehub
Install guide GitHub

Know what normal looks like on your plant network.

rehub runs Zeek, Suricata, tshark, YARA-X and tcpdump on OT captures, remembers the baseline, and tells you what a tool upgrade will change before you make it. It only listens.

Reads S7comm, EtherNet/IP and Modbus/TCP through the CISA ICSNPP parsers. Works on capture files you give it.

$ curl -fsSL https://raw.githubusercontent.com/Ani07-05/rehub/main/scripts/install.sh | sh
Read the script first Needs Docker running and git. Tested on macOS arm64.

What it will not do

  • Send a packet. No code path sends one and no active scanner is wrapped. CI fails if a raw socket, scapy send call or scanner name appears in the source.
  • Reach the network during analysis. Tools run in containers with networking off and read-only inputs. Only the install downloads anything.
  • Serve anyone else. The interface listens on 127.0.0.1 behind a private link. One analyst, no multi-user mode.
  • Prove anything about your plant. Doctor runs the tools over small synthetic captures and shows whether they behave the same. It does not predict what breaks on your traffic.
  • Parse more than three protocols. Suricata has no S7comm parser, so Zeek is the source for S7.

What an upgrade check looks like

Before you move sensors to a new tool version, rehub doctor replays the bundled fixtures through every tool and compares the result with the committed golden output.

$ rehub doctor
zeek 8.0.10: PASS
  enip_identity: PASS
  modbus_read_write: PASS
  s7_download_stop: PASS
  # a mismatch prints the changed version or fixture, e.g.
  version: zeek 9.0.0 (pinned 8.0.10)

Illustrative. The layout follows the command's output and the fixture names are the bundled ones. It is not a recorded run.

What the command does

It installs uv if you have none, clones rehub into ~/.rehub/src, pulls or builds the tool image, runs the doctor check, and opens the interface on your own machine. The last step keeps running until you press Ctrl+C.

  1. ==> Installing uv
  2. ==> Cloning rehub to ~/.rehub/src
  3. ==> Installing rehub
  4. ==> Creating ~/.rehub
  5. ==> Getting the tool image (a local build can take several minutes)
  6. ==> Checking the tools behave as pinned
  7. ==> Opening the interface (Ctrl+C to stop)

Step names from the script. Timings and tool output left out.

What it touches

  • Downloads. uv from astral.sh, rehub from github.com, and the tool image. The image is pulled from a registry when one is configured and built locally otherwise. A build also fetches Zeek, Suricata and YARA-X sources and Debian packages.
  • Writes. ~/.rehub (source, database, uploads, settings) and a rehub command in ~/.local/bin (rehub.cmd on Windows). uv's own installer may add itself to your shell profile. The script does not use sudo.
  • Runs. Docker containers, with networking off for analysis. The interface opens in your browser at 127.0.0.1.

If it stops, it prints why. Docker not running and missing git are checked first. Running the command again is safe: it updates the checkout and skips the image if it is already present. To remove rehub, delete ~/.rehub and ~/.local/bin/rehub, then run docker rmi rehub:pinned.

Pin what you run

The one-liner follows main, which can change after you read it. To audit and then run exactly what you read, download it, check it, and pin the checkout to the same tag or commit:

curl -fsSLO https://raw.githubusercontent.com/Ani07-05/rehub/<tag-or-sha>/scripts/install.sh
shasum -a 256 install.sh
less install.sh
REHUB_REF=<tag-or-sha> sh install.sh

On Windows, set $env:REHUB_REF to the same tag or commit before running install.ps1. Or run each step yourself:

git clone https://github.com/Ani07-05/rehub
cd rehub
uv sync
uv run rehub init
uv run rehub setup
uv run rehub doctor
uv run rehub web --open
